# 雕塑巡展运输与无障碍开放

协调雕塑巡展的运输安装、作品状况与无障碍公教开放。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构（当前 version 2），`fixtures/domain.json` 保存不含真实个人信息的示例（作者与批准人均以代号表示）。参与方包括巡展策展团队、作品出借方、艺术品承运安装人员、公教与无障碍服务人员。

资料所依据的领域事实：

- 巡展汇集九十二位创作者的一百零四件组作品
- 展览分三个叙事单元并跨地域交流
- 美术馆策划了邀请视障和残障观众参与的触摸活动

## 业务对象

`data` 下管理：创作者与作品（含组件、重量、支撑方式、借展条件、状态）、场馆与展厅点位（面荷载、锚固/供电/吊点/台座条件）、安装依赖、包装箱、车辆与运段、状况报告、交接与检查、触摸授权（作者确认 + 逐场馆确认、清洁间隔、分组人数、监督要求）、触摸场次、辅助讲解配置与预约。

## 规则模块（`src/`）

- `domain.js`：读取、校验必要字段、按标识建索引。
- `logistics.js`：包装箱毛重与箱体限重、运段车辆载重、点位面荷载对照展厅承重、修复/缺件/支撑/安装依赖导致的布展阻断。
- `access.js`：触摸双重授权判定（**普通展签不构成许可**）、撤回即全场馆停开、场次准入、已执行分组的清洁间隔/人数/监督核对、预约辅助需求覆盖与场次就绪判定。
- `roles.js`：最小知情视图——承运安装人员只见操作资料；公教人员可确认可触摸范围与清洁间隔但不见批准人身份；出借方只见作品状况与授权；策展团队全量可见。
- `trace.js`：策展追溯——从任一展出状态追到原状报告、包装箱/运段/交接移动路径、作者与各馆批准链条（含撤回事件）、面向特殊观众的实际开放结果。
- `events.js`：六类事件（修复、组件缺失、路线延误、场地变更、授权撤回、辅助需求变化）的只追加联动处理，并校验交接/检查/事件引用的留痕完整性。事件处理不修改入参，既往记录保留。

## 本地校验

```bash
npm test
```

运行项目自带的 43 条测试即可检查资料读取、运输承重、触摸准入、角色隔离、全链路追溯与事件联动。仓库不保存账号、密钥、连接串或真实身份信息。
