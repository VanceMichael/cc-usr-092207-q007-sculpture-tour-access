# 雕塑巡展运输与无障碍开放

协调雕塑巡展的运输安装、作品状况与无障碍公教开放。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括巡展策展团队、作品出借方、艺术品承运安装人员、公教与无障碍服务人员。

资料所依据的领域事实如下：

- 巡展汇集九十二位创作者的一百零四件组作品
- 作品按组件登记，运输方案取决于重量、支撑方式、借展条件与展厅点位承重
- 展览分三个叙事单元并跨地域交流
- 美术馆策划了邀请视障和残障观众参与的触摸活动
- 触摸开放只承认作者权利方与馆方安全负责人**双方确认且在有效期内**的授权；普通展签不构成许可

## 模块

纯函数式领域模型，数据与规则分离，所有人物均为岗位/代码，不含真实个人信息：

| 文件 | 职责 |
| --- | --- |
| `src/tour.js` | 聚合状态：作品与组件、作者权利、借展条件、包装箱、车辆与运输路段、装载、场馆点位、布展计划（含安装依赖）、触摸授权、预约场次；组装时做引用完整性校验 |
| `src/logistics.js` | 运输布展规则：车辆限载、隔离箱禁装、点位承重、支撑方式匹配、修复中/缺件禁展、安装依赖排序（`planVenueInstall`） |
| `src/touch.js` | 触摸许可：可触摸判定（展签不作为许可依据）、授权按场馆分别确认、清洁间隔与清洁记录、预约校验、实际触摸场次记录 |
| `src/changes.js` | 六类变更的联动：修复、组件缺失、路线延误、场地变更、授权撤回、辅助需求变化；以及装车/布展执行和 `traceWork` 策展追溯 |
| `src/events.js` | 交接与检查留痕：交接须交出方与接收方双签字，检查结论与发现必须一致 |
| `src/views.js` | 按角色裁剪可见资料（见下） |

示例数据见 `fixtures/tour.json`（4 件作品、4 个包装箱、1 条路段、2 个美术馆、2 项触摸授权、2 个预约）。

## 角色可见范围

- **承运/安装人员**（`carrier-install`）：作品重量、支撑方式、组件状况、包装箱、车辆路段限载、点位承重、布展顺序，以及职责内的交接检查记录；看不到借展条件、作者权利细节、触摸批准人和预约观众信息。
- **公教/无障碍人员**（`public-education`）：本馆当前可触摸作品清单、双方批准状态、有效期、**清洁间隔**与上次清洁时间、预约场次、辅助需求落实情况；看不到车辆、装载、包装箱等运输资料。
- **策展方**（`curatorial`）：全部资料，可从任一展出状态追到**作品原状**（基线状况报告）、**移动路径**（装车、交接、安装、场地变更）、**批准人**（每馆授权的作者方与馆方确认人，含撤回记录）和**面向特殊观众的实际开放结果**（实际举办的触摸场次与辅助使用）。

## 关键规则

1. **运输布展**：路段包装箱总重 ≤ 车辆限载；作品重 ≤ 点位承重且支撑方式被点位接受；安装依赖规定先后；修复中、组件缺失、隔离包装箱一律阻断。
2. **触摸授权**：作者方与馆方双方确认 + 在有效期内 + 作品状况完好；授权绑定场馆，换馆必须重新确认；作者声明 no-touch 时授权直接无效。
3. **清洁**：按授权间隔执行并留痕；未清洁或间隔到期，预约校验不通过。
4. **变更联动**：修复/缺件 → 暂停涉事作品后续场次（复检通过才恢复）；路线延误错过布展截止 → 目的馆场次暂停；场地变更 → 新点位物理约束重新校验、预约改挂且授权重新确认前暂停；授权撤回 → 作品移出场次，空场次取消；辅助需求无法落实 → 场次暂停，落实后自动恢复。
5. **留痕**：所有动作写入审计日志（执行岗位、时间、对象、双方签字），未通过校验的执行（如超载装车）不留痕。

## 本地校验

```bash
npm test
```

运行项目自带测试（35 项），检查示例资料读取、运输布展、触摸授权与清洁、变更联动、交接留痕和角色视图。仓库不保存账号、密钥、连接串或真实身份信息。
